The examiner hands you the wheel

A driving examiner does not ask you to recite the highway code. They say "pull out, take the second left". Your professor will do the same with the code: "make it do this instead".

The method never changes. Practise it on the four exercises below, on paper or in the repo, before you open the hints.

Exercise 1: add getprot(addr)

Return 1 if the page holding addr is writable, 0 if read-only, -1 if it is not a valid user page. Use system call number 24.

Hint

Copy the wiring of mprotect: syscall.h, syscall.c (extern and table), usys.S, user.h, defs.h. The helper looks up the entry with walkpgdir(…, 0) and tests PTE_W.

Answer
CODE · video/examples/getprot_solution.c · lines 6-17 
int
getuvmprot(pde_t *pgdir, uint sz, uint va)
{
  pte_t *pte;
 
  if(va >= sz)                       // outside the process
    return -1;
  pte = walkpgdir(pgdir, (void*)va, 0);   // 0 = never allocate
  if(pte == 0 || (*pte & PTE_P) == 0 || (*pte & PTE_U) == 0)
    return -1;                       // missing, not present, or kernel page
  return (*pte & PTE_W) ? 1 : 0;     // test the write bit only
}
PLAIN ENGLISH

The helper in vm.c. Take the page directory, process size and an address.

A local variable to hold the table entry.

An address outside the process is invalid, so return -1.

Look up the entry without creating anything.

Missing, not present, or not a user page: also -1.

Otherwise answer 1 if the write bit is set and 0 if not.

CODE · video/examples/getprot_solution.c · lines 20-28 
int
sys_getprot(void)
{
  int addr;
 
  if(argint(0, &addr) < 0)
    return -1;
  return getuvmprot(myproc()->pgdir, myproc()->sz, (uint)addr);
}
PLAIN ENGLISH

The system call wrapper in sysproc.c.

A variable for the address argument.

Fetch argument 0; if that fails return -1.

Call the helper with the current process page directory and size.

End.

Exercise 2: make len a count of bytes

mprotect(p, 5000) should protect two pages (round up). Zero and negative lengths are still invalid.

Hint

Only changeprotection() in sysproc.c changes. Convert bytes to pages before calling the helper, and avoid adding 4095 to a number that might be huge.

Answer
CODE · video/examples/bytes_solution.c · lines 12-18 
  if(argint(0, &addr) < 0 || argint(1, &len) < 0)
    return -1;
  if(len <= 0)                    // still reject zero and negative
    return -1;
  len = (len - 1) / PGSIZE + 1;   // bytes -> pages, rounded up
                                  // (never computes len + 4095, so no overflow)
  return setuvmwrite(curproc->pgdir, curproc->sz, (uint)addr, len, writable);
PLAIN ENGLISH

Fetch the two arguments as before.

A length of zero or less is still invalid.

Convert bytes to pages, rounding up: subtract one first, divide, add one.

The validating helper is unchanged. It now receives a page count.

Which existing tests would now fail? Any that pass a page count such as mprotect(p, 3): they now mean 3 bytes, which is one page.

Exercise 3: a clearer message on a write fault

When a user process writes a read-only page, print pid N name: write to read-only page 0x… before the usual trap line.

Hint

It goes in trap.c, in the user-space branch of the default case. Test for trap 14 with the error bits present, write and user.

Answer
CODE · video/examples/fault_message_solution.c · lines 7-9 
    if(tf->trapno == T_PGFLT && (tf->err & 7) == 7)   // present + write + user
      cprintf("pid %d %s: write to read-only page 0x%x\n",
              myproc()->pid, myproc()->name, PGROUNDDOWN(rcr2()));
PLAIN ENGLISH

Only for a page fault whose error code is "present + write + user" (7). Other faults keep the old message only.

Print the process id and name...

...and the page that was written, using rcr2() (the faulting address) rounded down to its page.

In the real run above, the output is pid 4 modtest: write to read-only page 0x3000 followed by the usual trap line, and the parent keeps running.

Exercise 4: refuse page 0, and allow at most 16 pages

Hint

Both rules belong in the first check of the shared helper, so they apply to both calls. Only a range that starts at address 0 can include page 0.

Answer
CODE · video/examples/limits_solution.c · lines 9-11 
  if(va % PGSIZE != 0 || npages <= 0 || npages > 16      // cap: at most 16 pages
     || va == 0 || va >= sz)                             // refuse page 0
    return -1;
PLAIN ENGLISH

Add npages > 16 to the rejection test: the cap.

Add va == 0: refuse any range that starts at page 0.

Return -1 as before. Nothing has been touched.

Tested in the guest: page 0 is refused, 16 pages work, 17 returns -1, and munprotect obeys the same cap.
